# 屋台レジ v2 セットアップ・使い方

お祭り屋台向けのレジ(会計・受け渡し・現金管理)です。複数のスマホ/タブレットで同じデータを共有するため、
データの保管に **Supabase**(無料プランで可)を使います。

公開URL(変わりません): **https://ds455hid-ai.github.io/kiyora-regi/**

> **ログインはありません。** 端末ごとに最初に「名前」を1回入れるだけで使えます(パスワード不要)。
> そのかわり **URLを知っている人は誰でも会計・売上の閲覧・返金・営業終了などができます**。URLを広く共有しないでください。
> (後から「合言葉」や管理者用の暗証番号を付けることもできます。必要になったら言ってください。)

## 使い方

| 場面 | 操作 |
| --- | --- |
| 最初だけ | 各端末でURLを開き、名前(ニックネームでOK)を入れる。右上の名前をタップするといつでも変更できます。 |
| 営業開始 | **管理 → 営業 → 営業開始**(釣銭を金種ごとに入力)。注文番号は毎営業日 001 から。 |
| 会計 | **レジ** 画面で商品をタップ → お預かり金額(1000/2000/5000/10000 ボタン・数字入力・ぴったり)→ **会計確定**。大きく出る **注文番号** をお客様へ口頭で伝えます。 |
| 受け渡し | **受け渡し** 画面に全員の注文が即時表示。品目ごとの提供(＋/−)か **提供完了**。他の人が先に押していたら自動で最新に更新され、二重提供になりません。 |
| 売り切れ | **管理 → 商品** の「売り切れにする」。レジのボタンが売り切れ表示になります。 |
| 返金・取消 | **売上 → 注文履歴 → 取消・返金**(現金残高も自動で戻ります)。 |
| 釣銭補充・売上回収 | **現金 → 補充 / 回収**。 |
| 営業終了 | **現金 → レジ締め**(金種別の枚数を入力 → 理論残高との過不足を確認)。 |
| 売上 CSV | **売上 → 営業日別 → 売上CSV / 現金CSV / 全期間CSV**。 |

### 電波が悪いとき
- 画面上部に赤い帯が出ます。会計は送信されません(電波が戻ると自動で最新に更新)。
- 会計確定の直後に電波が切れた場合は「**再送**」ボタンが出ます。同じ会計は **二重登録されません**。
- アプリを閉じても、未確認の会計は端末に保存されているので、開き直すと再送できます。

### 注意
- Supabase の **Free プランは、7 日間まったく使われないとプロジェクトが一時停止** します。
  開催の 1 週間前にダッシュボードを開いて、停止していたら「Restore」を押してください。
  イベント前に一度、アプリで会計テストをしておくのも確実です。
- 現金の「理論残高」は、開始釣銭 + 現金売上 − 返金 + 補充 − 回収 で、データベースが計算します。
- 旧レジ(v1)は `https://ds455hid-ai.github.io/kiyora-regi/legacy/index.html` に残っています。
  旧レジの取引履歴(各端末のブラウザ内データ)は削除していません。新レジの「管理 → その他」から書き出せます。

## 公開・ロールバック

- **公開**: `npm run deploy`(秘密鍵の混入を拒否 → 型チェック → 全テスト → ビルド → `gh-pages` ブランチへ反映)。
  反映前の状態は `deploy-backup-日時` タグに保存されます。
- **元に戻す(旧レジへ)**: GitHub の Settings → Pages → Branch を `backup/legacy-v1` に切り替えるだけで、旧レジに戻ります。

## 動作チェック(任意)

```bash
cd ~/kiyora-regi && npm run verify:supabase
```
2 台の端末のつもりで、同時会計・二重提供・二重返金・リアルタイム同期・直接書き込み拒否を本物の Supabase で確認します
(ログイン不要。営業日のデータがすでにある状態では安全のため中断します)。
終わったら Supabase の SQL Editor で `supabase/maintenance/reset_test_data.sql` を実行すると、テスト会計が消えます。

## 仕組み(開発者向けメモ)

- フロント: Vite + React + TypeScript(静的ビルド、`base=/kiyora-regi/`、ハッシュルーティング、PWA)
- バックエンド: Supabase(PostgreSQL / RLS / Realtime)。ログインは使わず、未ログイン(anon)キーで接続。
  担当者名はリクエストヘッダー `x-staff-name`(パーセントエンコード)で渡して記録します。
- 会計確定・連番・提供・返金・現金は **すべてデータベースの RPC(security definer 関数)** で実行。
  テーブルは端末から読み取り専用(直接の書き込みは権限で拒否)。行ロック(営業日 → 注文 → 明細の順)・一意制約・冪等キー(`request_id`)で整合性を保証。
- テスト: `npm test`(PostgreSQL ロジック + 本物の PostgreSQL での同時実行 + 計算ロジック)
- ローカル確認: `npm run dev:mock`(本番と同じ SQL をブラウザ内 PostgreSQL で実行する開発用モード。本番ビルドには含まれません)
